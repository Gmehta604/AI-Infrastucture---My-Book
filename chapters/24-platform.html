The AI Platform: Kubernetes, Schedulers and MLOps

Individual models and services need a platform underneath: something that allocates scarce GPUs fairly, deploys and scales model servers, runs training jobs, tracks experiments and models, and keeps costs visible. This is the day job of most "ML platform" and "AI infrastructure" engineers.

GPUs on Kubernetes

  1. NVIDIA GPU Operator installs drivers, the container toolkit, the device plugin (so pods can request nvidia.com/gpu), DCGM exporter for metrics, and the network operator for RDMA.
  2. Dynamic Resource Allocation (DRA), stable in recent Kubernetes versions, gives richer GPU requests (specific models, partitions, topology).
  3. Sharing: MIG (Multi-Instance GPU) splits an A100/H100/B200 into isolated slices; time-slicing and MPS share without isolation. Good for small models and notebooks.
  4. Queueing and fairness: Kueue or Volcano provide quotas per team, gang scheduling (all pods of a distributed job start together or none do), preemption and borrowing of idle quota.

Autoscaling model servers

CPU-based autoscaling is useless for LLM servers; scale on signals that reflect load:

  • Queue depth / pending requests (e.g., vLLM's vllm:num_requests_waiting).
  • KV cache utilisation (vllm:gpu_cache_usage_perc or equivalent).
  • Latency SLO (p95 TTFT approaching the limit).

Tools: KEDA (event-driven autoscaling from Prometheus metrics), Knative/KServe (with scale-to-zero), Ray Serve autoscaling, and the Kubernetes Gateway API Inference Extension for model-aware load balancing.

# KEDA: scale on waiting requests, down to zero at night
apiVersion: keda.sh/v1alpha1
kind: ScaledObject
metadata: { name: qwen-7b-scaler }
spec:
  scaleTargetRef: { name: qwen-7b }
  minReplicaCount: 0
  maxReplicaCount: 8
  cooldownPeriod: 600
  triggers:
    - type: prometheus
      metadata:
        serverAddress: http://prometheus.monitoring:9090
        query: sum(vllm:num_requests_waiting{app="qwen-7b"})
        threshold: "10"

The cold-start problem

Scale-to-zero saves money, but a new replica must pull a multi-GB container image, download tens or hundreds of GB of weights, load them into GPU memory and warm up (compile CUDA graphs). That can take minutes. Fixes:

  • Cache weights on local NVMe or a fast shared filesystem; pre-pull images.
  • Stream weights directly into GPU memory (e.g., Run:ai Model Streamer, fastsafetensors).
  • GPU memory snapshotting and restore (CUDA checkpoint, CRIU-based approaches used by serverless GPU platforms such as Modal).
  • Keep a small warm pool; scale to zero only for rarely-used models.

Load balancing LLM traffic

Round-robin is bad for LLMs: requests differ wildly in cost, and routing a request to the replica that already has its prefix cached saves prefill. KV-cache-aware routing (llm-d, NVIDIA Dynamo, SGLang router, the Gateway API Inference Extension) scores replicas by cache overlap and current load.

FinOps for GPUs

  • Tag every job and deployment with team and project; report GPU-hours and dollars weekly.
  • Track utilisation, not just allocation. Idle reserved GPUs are the most common waste.
  • Use spot/preemptible instances for fault-tolerant jobs (evals, batch inference, checkpointed training).
  • Right-size: a 7B model on an 80 GB GPU may be better as two replicas on MIG slices or a cheaper L40S / RTX PRO 6000.
  • Schedule batch inference and evals into off-peak idle capacity.
Build it

Project 5: "We pay for idle GPUs overnight"

Business problem: a company runs 12 always-on GPU replicas for internal models whose traffic drops 90% at night and on weekends.

  1. Create a Kubernetes cluster with GPU nodes (a managed cloud cluster or a single-node k3s with one GPU is enough to learn).
  2. Install the NVIDIA GPU Operator, Prometheus and KEDA. Deploy vLLM as above.
  3. Autoscale on waiting requests with scale-to-zero. Measure cold-start time, then cut it using a node-local weight cache and pre-pulled images.
  4. Replay a 24-hour traffic pattern (compressed in time). Report GPU-hours and cost vs. always-on, plus p95 latency including cold starts.
