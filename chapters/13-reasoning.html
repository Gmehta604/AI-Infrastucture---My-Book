Reasoning Models and Test-Time Compute

In September 2024, OpenAI's o1 showed that letting a model "think" before answering, spending thousands of tokens on a hidden chain of thought, dramatically improves math, science and coding. By 2026, nearly every frontier model is a reasoning model with adjustable thinking effort. This changes the economics of inference completely.

From chain-of-thought prompting to trained reasoning

2022: chain-of-thought prompting. Wei et al. showed that adding "Let's think step by step" or worked examples made large models far better at multi-step problems. Writing intermediate steps gives the model more computation (more forward passes) and a scratchpad.

2022–23: self-consistency and search. Sample many reasoning chains and take the majority answer. Tree-of-Thoughts explores branches. These help but are bolted on.

2024–25: reasoning trained by RL. o1, then DeepSeek-R1, Gemini Thinking, Claude's extended thinking, Qwen QwQ/Qwen3, and others trained models with reinforcement learning (Chapter 12) to produce long, self-correcting reasoning before a final answer. The model learns when to verify, backtrack, try another approach, or decompose a problem.

Test-time scaling

The key empirical finding: accuracy increases roughly log-linearly with thinking tokens. You can buy capability at inference time rather than only at training time.

Method How it spends compute Notes
Longer single chain More thinking tokens Main mechanism in reasoning models; controlled by "effort" or a thinking budget
Parallel sampling + vote N independent answers, majority wins Simple; good for short answers
Best-of-N with a verifier N answers, a reward model or test suite picks one Great for code (run tests)
Parallel thinking / multi-agent Several reasoning threads that share findings Used in "heavy"/"deep think" modes of 2025–26 products
Tree search Explore branches with a value model Research; strong for math proofs

What reasoning did to the industry

  1. Inference became the dominant cost. A reasoning answer might use 5,000–50,000 tokens instead of 500. Agents that run for hours use millions. This is why 2025–26 hardware (Blackwell Ultra, Rubin, Rubin CPX, Groq-style LPUs) and software (disaggregated serving, Dynamo) focus on inference throughput and long-context decode.
  2. Latency became a product decision. APIs expose effort levels (low/medium/high/max) or thinking budgets. Routers (Chapter 20) decide when a query deserves deep thought.
  3. Benchmarks were rapidly saturated. AIME math, GPQA science and SWE-bench coding went from hard to near-solved in about 18 months. New benchmarks (Humanity's Last Exam, FrontierMath tiers, ARC-AGI-2/3, long-horizon agent tasks) keep appearing.
  4. Hidden reasoning raised safety questions. Can we trust and monitor what a model thinks? Research on chain-of-thought faithfulness and monitorability asks whether visible reasoning reflects the real computation (Chapter 27).

Controlling reasoning via APIs

# Anthropic Messages API: extended thinking with a budget
import anthropic
client = anthropic.Anthropic()
resp = client.messages.create(
    model="claude-opus-5-5",           # use the current model id from the docs
    max_tokens=16000,
    thinking={"type": "enabled", "budget_tokens": 8000},
    messages=[{"role": "user", "content": "How many primes are below 10,000? Show a method."}],
)
for block in resp.content:
    print(block.type)                  # 'thinking' then 'text'

# OpenAI Responses API: reasoning effort
from openai import OpenAI
out = OpenAI().responses.create(
    model="gpt-5.5",                   # check current model names
    reasoning={"effort": "high"},
    input="Prove that the square root of 2 is irrational.",
)
print(out.output_text)

Parameter names change between API versions, so treat these as the shape of the idea and check the current documentation.

Why RL produces reasoning (intuition)

During RL on verifiable problems, a response that happens to double-check its arithmetic is more often correct, so it receives more reward, so the behaviour of double-checking is reinforced. Over thousands of steps, useful strategies (decomposition, verification, backtracking) are selected and lengthened. Nobody writes these strategies down; they are discovered, like AlphaGo's moves. That is the "bitter lesson" again: general methods plus compute beat hand-designed reasoning.

Limits and open problems

  • Overthinking: models spend thousands of tokens on trivial questions. Adaptive thinking and length penalties help.
  • Verifiability gap: RL works best where answers can be checked. Extending to open-ended tasks (writing, strategy, research taste) relies on rubric-based rewards and LLM judges, which can be gamed.
  • Long-horizon agency: thinking for minutes is solved; working reliably for days on a project is the 2026 frontier, measured by task-length metrics like METR's "time horizon," which has been doubling roughly every 4–7 months.
Build it

Project: A "thinking budget" router that cuts cost without hurting accuracy

Business problem: a support-automation company switched to a reasoning model and its bill tripled. Most tickets are easy.

  1. Collect 500 representative queries with correct answers.
  2. Run each at effort low, medium and high (or thinking budgets of 0, 2k, 8k tokens). Record accuracy, tokens and latency.
  3. Train a small classifier (Chapter 3) on query features or embeddings to predict the lowest effort that still answers correctly.
  4. Report the cost–accuracy curve: "Router saves 58% of spend at a 0.5-point accuracy loss."
