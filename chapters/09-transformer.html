Attention and the Transformer

This is the most important chapter in the book. Every frontier model in 2026 (GPT, Claude, Gemini, Llama, DeepSeek, Qwen) is a descendant of the architecture here. By the end you will have written a modern Llama-style Transformer from scratch.

The big picture

A decoder-only Transformer (the GPT family) is a stack of identical blocks. Each block has two sub-layers: attention, where tokens exchange information, and a feed-forward network (MLP), where each token processes what it gathered. Both are wrapped in normalisation and residual connections.

Architectures come in three flavours:

Type Attention Examples Good at
Encoder-only Bidirectional BERT, embedding models Classification, embeddings, rerankers
Encoder-decoder Bidirectional encoder, causal decoder T5, Whisper, original Transformer Translation, speech
Decoder-only Causal (only look left) GPT, Claude, Llama, all frontier chat models Generation; the dominant design

Self-attention, precisely

Each token's vector x is projected into three vectors with learned matrices:

  • Query q = x·W_Q: "what am I looking for?"
  • Key k = x·W_K: "what do I contain?"
  • Value v = x·W_V: "what do I pass on if selected?"

For a sequence packed into matrices Q, K, V (each of shape T × d):

Attention(Q, K, V) = softmax( Q·Kᵀ / √d + mask ) · V
  • Q·Kᵀ is a T×T matrix of dot products: how relevant each token is to each other token.
  • Dividing by √d keeps scores from growing with dimension, which would saturate the softmax.
  • The causal mask sets scores for future positions to −∞, so token t can only see tokens ≤ t. This is what lets one training sequence provide T training examples at once.
  • Softmax turns each row into weights; multiplying by V blends the values.

Multi-head attention

Instead of one attention with d=4096, split into, say, 32 heads of 128 dimensions. Each head can attend to different things: one tracks syntax, another the previous token, another a named entity. Outputs are concatenated and mixed by an output projection W_O.

Grouped-query attention (GQA) and friends

At inference, the model caches K and V for every past token (the KV cache, Chapter 19). With 32 heads, that cache is large. Variants shrink it:

Variant K/V heads KV cache size Used by
Multi-head (MHA) Same as query heads (e.g., 32) 1× GPT-2, GPT-3
Multi-query (MQA) 1 1/32× PaLM, Falcon
Grouped-query (GQA) A few groups (e.g., 8) 1/4× Llama 2 70B+, Llama 3, Qwen, Mistral
Multi-head latent (MLA) Compressed low-rank latent ~1/10× or less DeepSeek V2/V3/V4, Kimi K2

MLA stores a small compressed vector per token and reconstructs keys and values from it. It is one reason DeepSeek serves so cheaply.

The feed-forward network

After attention, each token passes independently through an MLP that expands to a larger hidden size and back. Modern models use SwiGLU:

FFN(x) = W_down · ( SiLU(x·W_gate) ⊙ (x·W_up) )

The FFN holds about two-thirds of a dense model's parameters and is where much factual knowledge appears to be stored. In mixture-of-experts models (Chapter 11), it is replaced by many expert FFNs, with only a few active per token.

Where the parameters and FLOPs go

For a model with d_model = d, L layers, a SwiGLU FFN of hidden size d_ff, and vocabulary V:

  • Attention per layer: about 4d² parameters (Q, K, V, O; less with GQA).
  • SwiGLU FFN per layer: 3 · d · d_ff (with d_ff ≈ 2.7d–3.5d, about 8d²–10d²).
  • Total ≈ L · 12d² plus embeddings V·d (a rough rule for standard FFN sizes).

Llama-3-8B: d=4096, L=32, d_ff=14,336, GQA with 8 KV heads, V=128,256 → about 8.0B parameters. Try computing it yourself.

d, L, dff, V, n_kv, hd = 4096, 32, 14336, 128256, 8, 128
attn = d*d + 2*d*(n_kv*hd) + d*d          # Wq, Wk, Wv (GQA), Wo
ffn = 3 * d * dff
total = L*(attn + ffn + 2*d) + 2*V*d + d  # untied embedding and LM head
print(f"{total/1e9:.2f}B")                # ≈ 8.03B

Build a modern GPT from scratch

This is a compact but real Llama-style model: RMSNorm, RoPE, GQA, SwiGLU, weight tying, causal attention through PyTorch's fused scaled_dot_product_attention (which dispatches to FlashAttention on GPUs), and generation with a KV cache.

import math, torch, torch.nn as nn, torch.nn.functional as F
from dataclasses import dataclass

@dataclass
class Config:
    vocab: int = 32_000
    d: int = 512
    n_layers: int = 8
    n_heads: int = 8
    n_kv_heads: int = 2          # GQA: 4 query heads share each K/V head
    ffn_mult: float = 8 / 3
    max_len: int = 1024
    rope_base: float = 10_000.0

class RMSNorm(nn.Module):
    def __init__(self, d, eps=1e-6):
        super().__init__(); self.eps = eps; self.w = nn.Parameter(torch.ones(d))
    def forward(self, x):
        return self.w * x * torch.rsqrt(x.pow(2).mean(-1, keepdim=True) + self.eps)

def rope_tables(head_dim, max_len, base):
    inv = 1.0 / (base ** (torch.arange(0, head_dim, 2).float() / head_dim))
    ang = torch.outer(torch.arange(max_len).float(), inv)       # (T, hd/2)
    return ang.cos(), ang.sin()

def apply_rope(x, cos, sin):
    # x: (B, H, T, hd). Rotate each pair (x1, x2) by the position's angle.
    x1, x2 = x[..., 0::2], x[..., 1::2]
    out = torch.stack([x1 * cos - x2 * sin, x1 * sin + x2 * cos], dim=-1)
    return out.flatten(-2)

class Attention(nn.Module):
    def __init__(self, c: Config):
        super().__init__()
        self.h, self.kvh, self.hd = c.n_heads, c.n_kv_heads, c.d // c.n_heads
        self.wq = nn.Linear(c.d, self.h * self.hd, bias=False)
        self.wk = nn.Linear(c.d, self.kvh * self.hd, bias=False)
        self.wv = nn.Linear(c.d, self.kvh * self.hd, bias=False)
        self.wo = nn.Linear(self.h * self.hd, c.d, bias=False)

    def forward(self, x, cos, sin, cache=None):
        B, T, _ = x.shape
        q = self.wq(x).view(B, T, self.h, self.hd).transpose(1, 2)
        k = self.wk(x).view(B, T, self.kvh, self.hd).transpose(1, 2)
        v = self.wv(x).view(B, T, self.kvh, self.hd).transpose(1, 2)
        q, k = apply_rope(q, cos, sin), apply_rope(k, cos, sin)
        if cache is not None:                          # append to KV cache
            if cache.get("k") is not None:
                k = torch.cat([cache["k"], k], dim=2)
                v = torch.cat([cache["v"], v], dim=2)
            cache["k"], cache["v"] = k, v
        rep = self.h // self.kvh                       # expand K/V heads for GQA
        k, v = k.repeat_interleave(rep, 1), v.repeat_interleave(rep, 1)
        # causal only when processing more than one new token (prefill/training)
        y = F.scaled_dot_product_attention(q, k, v, is_causal=(T > 1 and k.shape[2] == T))
        return self.wo(y.transpose(1, 2).reshape(B, T, -1))

class SwiGLU(nn.Module):
    def __init__(self, c: Config):
        super().__init__()
        hidden = int(c.ffn_mult * c.d)
        self.gate = nn.Linear(c.d, hidden, bias=False)
        self.up = nn.Linear(c.d, hidden, bias=False)
        self.down = nn.Linear(hidden, c.d, bias=False)
    def forward(self, x):
        return self.down(F.silu(self.gate(x)) * self.up(x))

class Block(nn.Module):
    def __init__(self, c):
        super().__init__()
        self.n1, self.attn, self.n2, self.ffn = RMSNorm(c.d), Attention(c), RMSNorm(c.d), SwiGLU(c)
    def forward(self, x, cos, sin, cache=None):
        x = x + self.attn(self.n1(x), cos, sin, cache)   # pre-norm + residual
        return x + self.ffn(self.n2(x))

class GPT(nn.Module):
    def __init__(self, c: Config):
        super().__init__()
        self.c = c
        self.emb = nn.Embedding(c.vocab, c.d)
        self.blocks = nn.ModuleList(Block(c) for _ in range(c.n_layers))
        self.norm = RMSNorm(c.d)
        self.head = nn.Linear(c.d, c.vocab, bias=False)
        self.head.weight = self.emb.weight               # weight tying
        cos, sin = rope_tables(c.d // c.n_heads, c.max_len, c.rope_base)
        self.register_buffer("cos", cos, persistent=False)
        self.register_buffer("sin", sin, persistent=False)
        self.apply(self._init)                           # small init keeps initial logits sane

    @staticmethod
    def _init(m):
        if isinstance(m, (nn.Linear, nn.Embedding)):
            nn.init.normal_(m.weight, mean=0.0, std=0.02)

    def forward(self, idx, targets=None, caches=None, start=0):
        T = idx.shape[1]
        cos, sin = self.cos[start:start + T], self.sin[start:start + T]
        x = self.emb(idx)
        for i, blk in enumerate(self.blocks):
            x = blk(x, cos, sin, None if caches is None else caches[i])
        logits = self.head(self.norm(x))
        loss = None
        if targets is not None:
            loss = F.cross_entropy(logits.reshape(-1, logits.size(-1)), targets.reshape(-1))
        return logits, loss

    @torch.no_grad()
    def generate(self, idx, max_new=50, temperature=0.8, top_p=0.95):
        caches = [dict() for _ in self.blocks]
        logits, _ = self(idx, caches=caches)            # prefill: whole prompt at once
        pos = idx.shape[1]
        for _ in range(max_new):                         # decode: one token per step
            probs = F.softmax(logits[:, -1] / temperature, dim=-1)
            sp, si = probs.sort(descending=True)         # nucleus (top-p) sampling
            sp[(sp.cumsum(-1) - sp) > top_p] = 0
            nxt = si.gather(-1, torch.multinomial(sp / sp.sum(-1, keepdim=True), 1))
            idx = torch.cat([idx, nxt], dim=1)
            logits, _ = self(nxt, caches=caches, start=pos)
            pos += 1
        return idx

model = GPT(Config())
print(sum(p.numel() for p in model.parameters()) / 1e6, "M params")
x = torch.randint(0, 32_000, (2, 64))
logits, loss = model(x[:, :-1], targets=x[:, 1:])
print(logits.shape, loss.item())          # loss ≈ ln(32000) ≈ 10.4 at init
print(model.generate(x[:, :8], max_new=5).shape)

Notice the two phases in generate: prefill processes the prompt in one parallel pass; decode then feeds one token at a time, reusing cached keys and values. The entire field of inference optimisation (Chapter 19) is about making these two phases fast.

Training it on real text

# Tiny Shakespeare with a character-level vocab, to see learning in minutes
text = open("input.txt").read()   # download tinyshakespeare from Karpathy's char-rnn repo
chars = sorted(set(text)); stoi = {c: i for i, c in enumerate(chars)}
data = torch.tensor([stoi[c] for c in text])
cfg = Config(vocab=len(chars), d=256, n_layers=6, n_heads=8, n_kv_heads=2, max_len=256)
model = GPT(cfg).cuda()
opt = torch.optim.AdamW(model.parameters(), lr=1e-3, weight_decay=0.1)
for step in range(3000):
    ix = torch.randint(len(data) - 257, (64,))
    xb = torch.stack([data[i:i + 256] for i in ix]).cuda()
    yb = torch.stack([data[i + 1:i + 257] for i in ix]).cuda()
    with torch.autocast("cuda", dtype=torch.bfloat16):
        _, loss = model(xb, yb)
    opt.zero_grad(); loss.backward(); opt.step()
    if step % 500 == 0: print(step, loss.item())

Decoding strategies

Strategy How Use
Greedy Always pick the most likely token Deterministic tasks; can loop
Temperature Scale logits before softmax Control randomness
Top-k Sample from the k most likely Cut off the long tail
Top-p (nucleus) Sample from the smallest set with cumulative prob ≥ p Default for chat
Min-p Keep tokens with prob ≥ p × max prob Popular in open-model community
Beam search Track several candidate sequences Translation; rarely for chat
Constrained / structured Mask tokens that would break a grammar (JSON schema) Reliable JSON and tool calls

What a Transformer learns internally

Interpretability research has found recognisable circuits: induction heads that copy patterns ("if A was followed by B before, predict B after A again"), which underlie in-context learning; features for concepts that can be found with sparse autoencoders; and attention heads that track syntax.
