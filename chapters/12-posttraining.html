Post-Training: From Base Model to Assistant

A pretrained base model is a brilliant autocomplete, not an assistant. Ask it a question and it may continue with three more questions. Post-training turns it into something helpful, honest and safe, and since 2024 it has also become the main route to reasoning ability. This chapter covers SFT, RLHF, DPO, constitutional methods and reinforcement learning with verifiable rewards.

The post-training pipeline

Real pipelines loop: several rounds of SFT and RL, with data from each round feeding the next.

Stage 1: Supervised fine-tuning (SFT)

Train on (prompt, ideal response) pairs formatted with the chat template. The loss is next-token prediction only on the response tokens (the prompt is masked out).

import torch.nn.functional as F

def sft_loss(model, input_ids, prompt_lens):
    logits, _ = model(input_ids[:, :-1])
    targets = input_ids[:, 1:].clone()
    for i, pl in enumerate(prompt_lens):
        targets[i, : pl - 1] = -100             # ignore prompt tokens
    return F.cross_entropy(logits.reshape(-1, logits.size(-1)),
                           targets.reshape(-1), ignore_index=-100)

Data: tens of thousands to millions of examples, from human writers, from stronger models (distillation), and from filtered model outputs. InstructGPT used about 13,000 human demonstrations; the LIMA paper (2023) showed 1,000 very high-quality examples can go a long way. Quality and diversity matter more than volume.

Stage 2: Learning from preferences

Writing perfect answers is hard; comparing two answers is easy. Preference methods exploit that.

RLHF with a reward model and PPO

  1. Reward model: a copy of the LLM with a scalar head, trained on pairwise comparisons using the Bradley–Terry loss: −log σ(r(chosen) − r(rejected)).
  2. RL: the policy generates responses; the reward model scores them; PPO (proximal policy optimisation) updates the policy.
  3. KL penalty against the SFT model stops reward hacking, where the policy finds outputs the reward model loves but humans do not (e.g., excessive length or flattery).

PPO is infrastructure-heavy: four models in memory (policy, reference, reward, value/critic), and a generation phase inside the training loop. Frameworks like OpenRLHF, veRL, TRL, NeMo-RL and slime exist mainly to orchestrate that.

Direct Preference Optimisation (DPO)

DPO (2023) showed you can skip the reward model and RL loop entirely. It optimises the policy directly on preference pairs with a classification-style loss:

L = −log σ( β · [ log πθ(y_w|x)/π_ref(y_w|x) − log πθ(y_l|x)/π_ref(y_l|x) ] )

where y_w is the preferred response and y_l the rejected one.

def dpo_loss(pol_chosen_lp, pol_rejected_lp, ref_chosen_lp, ref_rejected_lp, beta=0.1):
    # each argument: summed log-prob of the response tokens, shape (B,)
    logits = beta * ((pol_chosen_lp - ref_chosen_lp) - (pol_rejected_lp - ref_rejected_lp))
    return -F.logsigmoid(logits).mean()

DPO is simple and stable, and it became the default in open-source post-training. Variants: IPO, KTO (needs only thumbs-up/down), ORPO, SimPO.

Constitutional AI and AI feedback

Anthropic's Constitutional AI (2022) replaced much human harm-labelling with a written set of principles. The model critiques and revises its own outputs against the principles (supervised stage), then an AI judge produces preference labels (RLAIF). This scales feedback and makes the values being trained explicit. Most labs now use large amounts of AI-generated feedback, with humans auditing.

Stage 3: Reinforcement learning with verifiable rewards (RLVR)

The breakthrough of 2024–2025. For tasks where correctness can be checked automatically (math answers, code that passes unit tests, a web task that succeeds), you do not need a learned reward model. Generate many attempts, reward the correct ones, and reinforce.

GRPO (group relative policy optimisation, from DeepSeekMath 2024 and used in DeepSeek-R1) removes PPO's value network: sample a group of answers per prompt and use each answer's reward relative to the group average as its advantage.

import torch

def grpo_advantages(rewards):            # rewards: (num_prompts, group_size)
    mean = rewards.mean(dim=1, keepdim=True)
    std = rewards.std(dim=1, keepdim=True) + 1e-6
    return (rewards - mean) / std

def grpo_loss(logp_new, logp_old, adv, clip=0.2):
    # per-token log-probs (B, T) for sampled responses; adv broadcast per response
    ratio = (logp_new - logp_old).exp()
    unclipped = ratio * adv
    clipped = ratio.clamp(1 - clip, 1 + clip) * adv
    return -torch.min(unclipped, clipped).mean()

r = torch.tensor([[1., 0., 0., 1., 1., 0., 0., 0.]])   # 8 attempts, 3 correct
print(grpo_advantages(r))                            # correct ones get positive advantage

What DeepSeek-R1-Zero showed (January 2025): applying this directly to a base model, with rewards only for correct final answers and correct format, caused the model to spontaneously learn to reason at length, check its work, and backtrack ("wait, let me reconsider"). Response length grew steadily during training. This is the recipe behind the reasoning models of Chapter 13.

The RL infrastructure problem

RL for LLMs alternates between generation (inference, often 70–90% of wall-clock time) and training. Modern systems:

Hard problems: long-tail generation latency (a few very long responses stall the batch), fast weight synchronisation from trainer to inference engines, running thousands of secure code sandboxes, and asynchronous/off-policy RL to keep GPUs busy. Reward hacking is common: models learn to special-case unit tests or edit the test file. Environment design is now a core research and engineering discipline, and a startup category ("RL environments").

Distillation

A large "teacher" model generates outputs (or full probability distributions) and a small "student" trains on them. DeepSeek distilled R1's reasoning traces into Qwen and Llama models from 1.5B to 70B parameters, producing small models that reason far better than their size suggests. Most small commercial models are distilled from larger ones.

Model merging

Averaging or combining weights of fine-tuned variants (model soups, TIES, DARE, SLERP) can combine skills without further training. It is common in the open-model community and used by some labs between RL stages.

Build it

Project: Teach a small model a verifiable skill with GRPO

Business problem: an operations team needs a cheap model that reliably extracts structured fields (dates, amounts, IDs) from messy emails into valid JSON. Frontier API calls cost too much at their volume.

  1. Start from a 0.5B–3B open instruct model.
  2. Build a verifier: reward 1.0 if the output parses as JSON matching the schema and fields match ground truth; partial credit per field.
  3. Run SFT on 1,000 examples, then GRPO with Hugging Face TRL (GRPOTrainer) or Unsloth on a single GPU.
  4. Compare: accuracy and cost per 1,000 emails vs. a frontier API. Watch for reward hacking (e.g., empty-but-valid JSON).
