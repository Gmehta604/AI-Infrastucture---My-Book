Mixture of Experts and Modern Architectures

The 2017 Transformer has been refined rather than replaced. The biggest change is sparsity: mixture-of-experts models with hundreds of billions or trillions of parameters, of which only a small fraction runs per token. This chapter covers MoE, long context, and the linear-attention and state-space hybrids reshaping 2026 architectures.

Mixture of Experts (MoE)

A dense model uses every parameter for every token. An MoE layer replaces the single FFN with many expert FFNs and a small router that picks the top-k experts for each token.

Why it works: capacity (total parameters, which store knowledge) is decoupled from compute (active parameters per token). DeepSeek-V3 has 671B total parameters but activates only 37B per token, so it computes like a ~37B dense model while knowing like a much bigger one.

Model Total params Active params Experts (routed / active)
Mixtral 8x7B (2023) 47B 13B 8 / 2
DeepSeek-V3 / R1 (2024–25) 671B 37B 256 / 8 + 1 shared
Qwen3-235B-A22B (2025) 235B 22B 128 / 8

gpt-oss-120b (2025) 117B 5.1B 128 / 4
GLM-5.x, DeepSeek V4, Qwen3.x-Max, Kimi K3 (2026) Several hundred B to multiple T Tens of B Fine-grained, many experts

Frontier closed models are widely believed to be MoE as well, though labs rarely confirm details.

Implementing an MoE layer

import torch, torch.nn as nn, torch.nn.functional as F

class Expert(nn.Module):
    def __init__(self, d, h):
        super().__init__()
        self.gate, self.up, self.down = nn.Linear(d, h, bias=False), nn.Linear(d, h, bias=False), nn.Linear(h, d, bias=False)
    def forward(self, x):
        return self.down(F.silu(self.gate(x)) * self.up(x))

class MoE(nn.Module):
    def __init__(self, d=512, h=1024, n_experts=16, top_k=2):
        super().__init__()
        self.router = nn.Linear(d, n_experts, bias=False)
        self.experts = nn.ModuleList(Expert(d, h) for _ in range(n_experts))
        self.shared = Expert(d, h)
        self.k, self.E = top_k, n_experts

    def forward(self, x):
        B, T, d = x.shape
        flat = x.reshape(-1, d)                              # (N, d) tokens
        probs = F.softmax(self.router(flat), dim=-1)         # (N, E)
        topw, topi = probs.topk(self.k, dim=-1)              # (N, k)
        topw = topw / topw.sum(-1, keepdim=True)
        out = torch.zeros_like(flat)
        for e in range(self.E):                              # dispatch per expert
            rows, slot = (topi == e).nonzero(as_tuple=True)
            if rows.numel():
                out[rows] += topw[rows, slot, None] * self.experts[e](flat[rows])
        # load-balancing auxiliary loss (Switch Transformer style)
        frac_tokens = F.one_hot(topi[:, 0], self.E).float().mean(0)
        frac_prob = probs.mean(0)
        aux = self.E * (frac_tokens * frac_prob).sum()
        return (out + self.shared(flat)).view(B, T, d), aux

y, aux = MoE()(torch.randn(2, 16, 512))
print(y.shape, aux.item())

The Python loop is for clarity. Production systems group tokens by expert and run grouped GEMMs (one kernel for many small matmuls), and in distributed training they send tokens to experts on other GPUs with an all-to-all collective (expert parallelism, Chapter 17).

MoE engineering problems

  1. Load balancing. If the router sends most tokens to a few experts, those GPUs overload while others idle. Fixes: an auxiliary balancing loss (above), or DeepSeek's auxiliary-loss-free method that adds a per-expert bias adjusted during training.
  2. Communication. All-to-all traffic between GPUs is heavy; this is why NVLink domains of 72 GPUs (GB200/GB300 NVL72) are so valuable for MoE.
  3. Memory. You must hold all experts in memory even though few are active. Serving a 1T-parameter MoE needs many GPUs even if compute per token is small.
  4. Training instability. Router logits can blow up; z-loss and careful initialisation help.

Long context

Context windows grew from 2K tokens (GPT-3) to 128K (2023–24) to 1M+ (Gemini 1.5 onward; common in 2026 open models). Ingredients:

  • RoPE scaling (position interpolation, NTK-aware scaling, YaRN) to extend a model trained on short sequences.
  • Long-context training stages near the end of pretraining with progressively longer sequences.
  • Efficient attention kernels (FlashAttention) so memory grows linearly, not quadratically.
  • Context parallelism / ring attention to split one long sequence across GPUs (Chapter 17).
  • Sparse and sliding-window attention: attend fully to recent tokens and sparsely to distant ones. Mistral and Gemma interleave sliding-window and global layers; DeepSeek's native sparse attention (NSA) and DSA select only relevant blocks of the past.

Evaluate long context with needle-in-a-haystack, RULER and multi-hop long-document tasks. "Supports 1M tokens" and "uses 1M tokens well" are different claims.

State-space models and linear attention

Attention's KV cache grows with context, and its compute grows quadratically. Recurrent alternatives keep a fixed-size state, just like RNNs, but are designed to train in parallel:

  • Mamba / Mamba-2 (2023–24): selective state-space models with input-dependent dynamics and a hardware-aware parallel scan.
  • RWKV, RetNet, Gated Linear Attention.
  • Gated DeltaNet (2024): linear attention with a "delta rule" update that overwrites stale memories.

Pure recurrent models lag at precise recall ("what was the 7th item in the list?"). The winning pattern is the hybrid: mostly linear/SSM layers with a few full attention layers.

Hybrid model Mix
Jamba (AI21, 2024) Mamba + attention + MoE
NVIDIA Nemotron-H / Nemotron 3 (2025) Mostly Mamba-2 with a few attention layers; MoE in Nemotron 3
Qwen3-Next / Qwen3.5+ (2025–26) Gated DeltaNet + gated attention, roughly 3:1, with sparse MoE
MiniMax-01 (2025) Lightning (linear) attention + softmax attention

Infrastructure impact: hybrids cut KV cache memory by roughly the fraction of non-attention layers, allowing much larger batches and longer contexts per GPU. Serving engines (vLLM, SGLang) had to add support for mixed cache types.

Other architectural refinements you will see

  • Multi-token prediction (MTP): train extra heads to predict tokens 2, 3… ahead. Improves training signal and enables speculative decoding for free (DeepSeek-V3).
  • QK-norm, logit soft-capping: stability at scale.
  • No biases, untied or tied embeddings, larger vocabularies.
  • Attention sinks and gated attention: control the tendency of attention to dump weight on the first token.
  • Diffusion language models (e.g., Inception's Mercury, Google's Gemini Diffusion research): generate many tokens in parallel by iterative denoising rather than left-to-right, promising much faster decoding.
