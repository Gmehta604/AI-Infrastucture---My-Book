Classical Machine Learning

Before deep learning there was machine learning, and it never went away. Fraud detection, credit scoring, ad ranking, demand forecasting and churn prediction still run largely on the methods in this chapter. More importantly, the vocabulary here (training, validation, overfitting, metrics) is the vocabulary of all of AI.

What "learning" means

A program learns when its performance on a task improves with experience (data). There are three main settings:

LLM pretraining is self-supervised: the "label" is simply the next word, which comes free with the text. That is why it scales to trillions of examples without human labelling.

The workflow every ML project follows

  • Training set: the model learns from it.
  • Validation set: you tune choices (hyperparameters) against it.
  • Test set: touched once, at the end, to report honest performance.

If you tune against the test set, you are fooling yourself. This is also the core problem with public LLM benchmarks: once they leak into training data, scores stop meaning much (Chapter 23).

Linear regression

Predict a number as a weighted sum of features: ŷ = w·x + b. Train by minimising mean squared error.

import numpy as np
rng = np.random.default_rng(0)
X = rng.uniform(0, 10, size=(200, 1))
y = 3.0 * X[:, 0] + 5 + rng.normal(0, 1, 200)      # true w=3, b=5

w, b, lr = 0.0, 0.0, 0.01
for epoch in range(2000):
    pred = w * X[:, 0] + b
    err = pred - y
    w -= lr * (2 * err * X[:, 0]).mean()           # dMSE/dw
    b -= lr * (2 * err).mean()                     # dMSE/db
print(f"w={w:.2f}  b={b:.2f}")                     # ≈ 3.00, 5.0

Notice that this is exactly the gradient-descent loop from Chapter 2. A neural network is this loop with a more complicated function.

Logistic regression: the ancestor of every classifier

For classification, pass the weighted sum through a sigmoid to get a probability between 0 and 1, and train with cross-entropy loss. The final layer of an LLM is essentially a giant multi-class logistic regression over ~100,000–250,000 tokens (softmax instead of sigmoid).

from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split
from sklearn.linear_model import LogisticRegression
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import make_pipeline

X, y = load_breast_cancer(return_X_y=True)
Xtr, Xte, ytr, yte = train_test_split(X, y, test_size=0.2, random_state=0)
clf = make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000))
clf.fit(Xtr, ytr)
print("accuracy:", clf.score(Xte, yte))

Decision trees, random forests, gradient boosting

A decision tree asks a sequence of yes/no questions ("income > 50k?"). Trees are interpretable but overfit easily.

  • Random forest: train hundreds of trees on random subsets of rows and features, then average. Averaging cancels out individual trees' errors (this is bagging).
  • Gradient boosting (XGBoost, LightGBM, CatBoost): train trees sequentially, each one correcting the errors of the ones before. For tabular data (spreadsheets, databases), gradient boosting is still usually the best method in 2026, often beating deep learning.
from sklearn.ensemble import RandomForestClassifier, HistGradientBoostingClassifier
for model in [RandomForestClassifier(n_estimators=300), HistGradientBoostingClassifier()]:
    model.fit(Xtr, ytr)
    print(type(model).__name__, model.score(Xte, yte))

Unsupervised learning

  • k-means clustering: pick k centres, assign each point to the nearest, move centres to the mean, repeat. Used in vector databases (IVF indexes, Chapter 21) and in quantization codebooks.
  • PCA: find the directions along which data varies most, and project onto the top few. Used for visualisation and compression.
from sklearn.cluster import KMeans
from sklearn.decomposition import PCA
X2 = PCA(n_components=2).fit_transform(X)
labels = KMeans(n_clusters=2, n_init=10).fit_predict(X2)

Overfitting, underfitting and the bias–variance trade-off

  • Underfitting (high bias): the model is too simple; it is bad on training and validation data.
  • Overfitting (high variance): the model memorised the training data; it is great on training data and bad on validation.

Cures for overfitting: more data, regularisation (L2 penalty on weights, called weight decay in deep learning), dropout, early stopping, simpler models.

Deep learning complicated this story. Very large networks trained on enough data show double descent: past a certain size, test error falls again as models grow. Huge LLMs are trained for about one pass (one "epoch") over their data, so classical overfitting is rare in pretraining. It returns with a vengeance in fine-tuning on small datasets (Chapter 18).

Metrics: choose them before you train

Task Metric When it misleads
Classification Accuracy Imbalanced data (99% "not fraud" gives 99% accuracy with a useless model)
Classification Precision = TP/(TP+FP) Ignores what you missed
Classification Recall = TP/(TP+FN) Ignores false alarms
Classification F1, ROC-AUC, PR-AUC PR-AUC is better for rare positives
Regression MAE, RMSE RMSE punishes large errors more
Ranking / search NDCG, MRR, Recall@k Used for RAG retrieval (Chapter 21)
Language models Perplexity, pass@k, win rate Covered in Chapter 23

Key idea. The metric is the business problem. A fraud model that catches 95% of fraud but flags 10% of legitimate customers may cost more than it saves. Always translate metrics into money or user impact.

Feature engineering vs. representation learning

In classical ML, humans design features (e.g., "number of transactions in the last hour"). Deep learning's promise is that the network learns the features itself from raw data (pixels, characters). That shift, from hand-crafted to learned representations, is the reason deep learning won in vision, speech and language, and why embeddings (Chapter 8) are so central.

Where classical ML lives in the modern stack

  • Ranking and recommendation systems at Meta, Google, TikTok, Amazon (often deep models, with gradient-boosted trees in parts of the pipeline).
  • LLM routers (Chapter 20) are frequently a small classifier deciding which model gets a request.
  • Anomaly detection on GPU cluster telemetry (predicting failing nodes).
  • Eval classifiers that score LLM outputs for toxicity or PII.

Project 0: A churn model with a cost-aware threshold

Business problem: a subscription company loses customers and wants to target retention offers.

  1. Take a public churn dataset (e.g., the Telco Customer Churn dataset on Kaggle).
  2. Train logistic regression and LightGBM. Compare ROC-AUC.
  3. Assign costs: a retention offer costs $20; a lost customer costs $300. Choose the probability threshold that maximises profit, not accuracy.
  4. Write a one-page memo: "At threshold X we contact Y% of customers and save $Z per month."

This teaches the discipline every later project needs: a metric tied to money.
