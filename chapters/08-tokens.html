Tokenization and Embeddings

A language model never sees text. It sees integers, called tokens, which it immediately turns into vectors, called embeddings. How text becomes tokens affects cost, speed, multilingual fairness and even arithmetic ability.

The pipeline from text to vectors

Why not characters or words?

  • Characters: tiny vocabulary, but sequences become 4–5× longer. Attention costs grow quadratically, so this is expensive.
  • Words: short sequences, but the vocabulary is enormous, and any unseen word ("GPT-6ification") is unknown.
  • Subwords (the answer): common words are single tokens; rare words split into pieces. "unbelievably" → un, believ, ably.

Byte-Pair Encoding (BPE)

BPE, used by GPT models, Llama 3+, Qwen and most others, learns merges from data:

  1. Start with bytes (256 base symbols), so any text is representable.
  2. Count every adjacent pair in the corpus.
  3. Merge the most frequent pair into a new symbol.
  4. Repeat until the vocabulary reaches the target size.
from collections import Counter

def train_bpe(text, num_merges):
    ids = list(text.encode("utf-8"))
    merges = {}
    for i in range(num_merges):
        pairs = Counter(zip(ids, ids[1:]))
        if not pairs:
            break
        best = max(pairs, key=pairs.get)
        new_id = 256 + i
        merges[best] = new_id
        out, j = [], 0
        while j < len(ids):                       # replace every occurrence
            if j < len(ids) - 1 and (ids[j], ids[j + 1]) == best:
                out.append(new_id); j += 2
            else:
                out.append(ids[j]); j += 1
        ids = out
    return merges, ids

text = "low lower lowest newer newest " * 50
merges, ids = train_bpe(text, 20)
print(len(text.encode()), "bytes ->", len(ids), "tokens")

In production you use a fast library:

import tiktoken                                  # OpenAI's BPE
enc = tiktoken.get_encoding("o200k_base")
ids = enc.encode("Tokenization affects cost!")
print(ids, [enc.decode([i]) for i in ids])

from transformers import AutoTokenizer          # Hugging Face
tok = AutoTokenizer.from_pretrained("Qwen/Qwen2.5-7B-Instruct")
print(tok("Tokenization affects cost!").input_ids)

Other algorithms: WordPiece (BERT) and Unigram / SentencePiece (T5, Gemma, many multilingual models).

Tokenization has real consequences

Effect Why Business impact
Cost APIs bill per token English averages ~0.75 words per token; many languages need 2–4× more tokens for the same meaning, so they cost more
Speed Decoding is one token per step Fewer tokens = faster responses
Arithmetic "12345" may split as 123 45 Models historically struggled with digit-level math; many tokenizers now split digits individually
Code Whitespace handling Good tokenizers merge runs of spaces
Glitch tokens Tokens that appeared in tokenizer training but rarely in model training Strange outputs (the famous "SolidGoldMagikarp")

Vocabulary sizes have grown: GPT-2 used 50,257 tokens; Llama 3 uses 128,256; GPT-4o's o200k has about 200,000; Gemma uses 256,000. Bigger vocabularies shorten sequences but enlarge the embedding and output layers.

Special tokens mark structure: <|begin_of_text|>, <|im_start|>user, tool-call markers, and end-of-sequence. Chat templates define how a conversation is laid out in tokens. Getting the template wrong when serving or fine-tuning an open model is one of the most common and silent bugs in the industry.

Embeddings

An embedding is a learned vector for each token. The embedding table is a matrix of shape (vocab_size, d_model); looking up a token is just selecting a row.

import torch.nn as nn
emb = nn.Embedding(num_embeddings=128_256, embedding_dim=4096)
print(emb.weight.numel() / 1e6, "M parameters")    # 525M in the table alone

During training, tokens used in similar contexts end up with similar vectors. Meaning becomes geometry: directions in the space correspond to concepts like gender, tense or sentiment.

Two kinds of embeddings: don't confuse them

  1. Token embeddings: the input layer of an LLM, one per vocabulary entry.
  2. Text / sentence embeddings: a single vector for a whole passage, produced by a dedicated embedding model (e.g., OpenAI text-embedding-3, Cohere Embed, Voyage, open models like BGE, E5, GTE, Nomic, Qwen3-Embedding). These power semantic search and RAG (Chapter 21).
from sentence_transformers import SentenceTransformer
m = SentenceTransformer("BAAI/bge-small-en-v1.5")
docs = ["How do I reset my password?", "Shipping takes 3-5 days.", "Refund policy for damaged items"]
q = m.encode("I forgot my login", normalize_embeddings=True)
D = m.encode(docs, normalize_embeddings=True)
print(D @ q)        # highest score = password doc

Positional information

Attention by itself treats input as an unordered set; "dog bites man" and "man bites dog" would look identical. Models must inject position:

  • Learned absolute position embeddings (GPT-2): a vector per position, added to token embeddings. Cannot extend beyond the trained length.
  • Sinusoidal (original Transformer): fixed sine/cosine patterns.
  • RoPE (rotary position embedding): rotates query and key vectors by an angle proportional to position, so their dot product depends on relative distance. The standard in nearly all modern LLMs. Context-extension tricks (NTK scaling, YaRN) work by adjusting RoPE frequencies.
  • ALiBi: adds a distance-based penalty to attention scores.
